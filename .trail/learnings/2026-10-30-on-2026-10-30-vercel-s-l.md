## Decided
Before any PR with a migration, check the Vercel env targets: DATABASE_URL, AUTH_SECRET and CRON_SECRET must each be Production only, with separate Preview values. As of 2026-10-31 they target both, and security.md says otherwise. The owner changes them by hand, as agreed in the Oct 28 incident.
src/modules/integrations/calendar.ts: a 401 from Calendar gets one forced token refresh and one more read. A 401 after that shows ACCESS_NOT_ACCEPTED, in place of "could not be reached".

## Tried and ruled out
Explaining the 401 by expiry or a disabled API: the token was 27 seconds old with an hour left, and a disabled API answers 403. The 401 cleared after the owner reconnected. Its cause was never found.

## Watch out
Evidence that a preview build ran on production: PR #25's build log says migrations applied, the `preview` Neon branch (br-sweet-boat-b3kjl5jp) stayed at 35 migrations without calendar_events, no per-PR Neon branch exists and no Neon integration is installed. This is strong evidence, not proof, because a build log doesn't name the host.
docs/DEPLOYMENT.md describes a Neon integration with a branch per preview, which this project doesn't have.
